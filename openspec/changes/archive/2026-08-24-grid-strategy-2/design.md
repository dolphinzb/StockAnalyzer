## Context

现有网格交易仿真（`src/composables/useGridSimulation.ts`）已实现"游标 + 虚拟卖出占位"模型，并在 `runGridSimulation(globalGrid)` 中按 **网格策略1** 运行：上涨穿越时一次性卖出当前批次的全部持仓（LIFO 出一整批，`lots: number[]`）。

用户希望在不改变策略1 的前提下，新增 **网格策略2**：上涨穿越时只卖出当前批次的「一半」，股价再上穿更高一级网格时再卖出剩余「另一半」，从而降低单笔清仓后踏空的风险。这是一项对既有卖出行为的扩展，保持买入、档位生成、费用、虚拟卖出占位等逻辑不变。

约束：
- 沿用「渲染进程直接计算、不新增 IPC 通道」的约定（与首版设计 D1 一致）。
- `GridSimulationInput` 已通过 `klineAPI.getChartData` 在渲染进程取得数据，`gridStrategy` 可作为普通字段透传，无需 IPC 变更。
- 改动须向后兼容：旧调用方不传 `gridStrategy` 时默认策略1，结果不变。

## Goals / Non-Goals

**Goals:**
- 在 `GridSimulationInput` 增加 `gridStrategy: 'strategy1' | 'strategy2'`（默认 `'strategy1'`）。
- 引擎按策略分支计算上涨卖出比例：策略1 整批清仓、策略2 分两次各卖一半。
- 前端 `GridSimulationView.vue` 增加「网格策略」下拉框（网格策略1 / 网格策略2），并在结果区标明当前所用策略。

**Non-Goals:**
- 不改动买入逻辑、档位生成、费用、虚拟卖出占位、收益指标计算。
- 不新增数据库表、不新增 IPC 通道、不引入第三方依赖。
- 不做多标的、不做实盘下单。

## Decisions

### D1 — 以策略字段参数化，而非复制整套算法
- **选择**：在 `GridSimulationInput` 增加 `gridStrategy` 字段，引擎内部用同一个 `runGridSimulation` 函数，仅在 `stepUp`（上涨卖出）处按字段分支。
- **备选**：复制一份 `runGridSimulationV2` 函数。
- **理由**：策略2 与策略1 的买入、档位、虚拟卖出、指标完全一致，仅卖出比例不同（1:1 → 1:½ + ½）。参数化复用率最高、回归面最小；单一函数避免两套逻辑日后漂移。

### D2 — 批次模型从 `number[]` 升级为 `{ total: number; sold: number; buyLevel: number }[]`
- **选择**：`lots` 由「每批股数的数组」改为「每批 {总股数, 已卖股数, 买入档位} 的对象数组」，仍为 LIFO 栈（末端为最近买入批次）。
- **理由**：策略2 需要把一笔批次拆成多段卖出（每次上涨穿越减半），必须记录「该批次已卖出多少」以及「该批次当初在哪个档位买入」，否则无法区分「已穿越待减」与「尚未穿越的新批次」，也无法在跨批次遍历时判定哪些批次要减半。对象结构让 `holding`（持仓）继续等于「各批次剩余之和」保持自洽，买入时 `push({total, sold:0, buyLevel})`，卖出时 `sold += 本次卖出`、`holding -= 本次卖出`。
- **影响**：原 `lots.pop()`（策略1 整批出栈）保留；策略2 改为遍历栈、对「已穿越待减」批次各减半、卖光的批次 `splice` 弹出。

### D3 — 上涨卖出（stepUp）按策略分支
- **策略1**（现状，保持不变）：`lots.pop()` 整批卖出（仅栈顶一批）。
- **策略2（跨批次分步减仓）**：每次上涨穿越，**所有「已穿越待减」的批次都各自减仓**，而非只处理栈顶一批。判定「已穿越待减」：`lot.buyLevel < sellLevel && lot.sold < lot.total - 1e-9`（买入价低于本次卖出档位、且尚未卖光，说明它已经历过至少一次上涨穿越）。每批分**两段**减仓：
  - 首次穿越（该批 `sold === 0`）：`sellShares = floorToLot(lot.total / 2)`（向下取整到 100 股）。
  - 之后穿越（该批 `sold > 0`）：`sellShares = lot.total - lot.sold`（卖剩余全部，即另一半）。
  - `lot.sold += sellShares; holding -= sellShares; cash += sellShares*price - fee`，为该批生成一条真实 SELL 记录；当 `lot.sold >= lot.total - 1e-9` 时 `lots.splice(i, 1)` 弹出该批次。
  - 同一档位穿越会产生**多条 SELL 记录**（每批一条），股数可不同；`cursorIdx += 1` 不变。
  - 若没有任何批次满足「已穿越待减」（所有批次买入价都 ≥ sellLevel，或栈空），则走虚拟卖出占位分支（与现状一致）。
- **为何跨批次而非仅栈顶**：用户明确确认——每次上涨穿越要把所有「已穿越待减」批次各自减仓。例：4.2 买入 2000、4.4 买入 2000；涨到 4.6 时，4.2 批（已穿越 4.4，卖过半）与 4.4 批（首次穿越）都属于「已穿越待减」，**应同时减仓**：4.2 批卖剩余 1000（清空弹栈）、4.4 批卖首次一半 1000（剩 1000）。这纠正了此前「只动栈顶一批」的理解。
- **示例（跨批次，分两段）**：4.2 买入 2000（lotA）→ 上穿 4.4 时 lotA 首次卖 1000（剩 1000）；4.4 买入 2000（lotB）→ 上穿 4.6 时 lotA 卖剩余 1000（清空弹栈）+ lotB 首次卖 1000（剩 1000）；再上穿 4.8 时 lotB 卖剩余 1000（清空弹栈）。

### D4 — 奇数/非整百批次的拆分处理
- 若某批次 `total` 不是 200 的整数倍（自动估算或手动填奇数），首次的 `floorToLot(total/2)` 会向下取整到 100 股，导致第二次「剩余全清」时把尾数一并卖出，从而保证**单批股数精确守恒**（仅首次会向下取整，尾数归第二次）。
- **选择**：首次取 `floorToLot(total / 2)`，第二次直接取「剩余 `total - sold`」；此差异仅在极小/异常股数时出现，且不影响核心「分两段各减一半」语义；UI 默认股数为 100 整数倍，常规场景均为等分。

### D5 — 前端下拉框与结果说明
- `GridSimulationView.vue` 表单新增「网格策略」`<select>`，选项：值 `'strategy1'` 标签「网格策略1」，值 `'strategy2'` 标签「网格策略2」，默认 `'strategy1'`。
- `buildInput()` 将 `form.gridStrategy` 写入 `GridSimulationInput`。
- 结果区「简化假设说明」卡片增加一行当前策略说明（如「当前策略：网格策略2（分步减仓）」），便于用户核对。

## Risks / Trade-offs

- **[Risk] 策略2 在多次上下震荡时，同一批次可能被反复「半卖/半留」，导致持仓长期处于半仓状态** → 这是策略本身的特性（锁利+留仓），非 bug；与策略1 相比回撤与收益特征不同，用户在 UI 可对比两种策略，无需特殊处理。
- **[Risk] 批次对象重构影响既有逻辑** → 买入、虚拟卖出、持仓统计均围绕 `holding` 与 `lots` 同步更新，重构后逐项核对 `holding === Σ(total - sold)`，并在 `tests/` 增加策略2 单测覆盖示例场景。
- **[Risk] floor-to-100 导致非整两百批次拆分不均** → 已在 D4 明确「尾数归第二次」规则，并在 spec 场景中以「默认整百股数」为主场景，异常场景容忍不等分。

## Migration Plan

- 纯前端改动，无后端/数据库迁移；`gridStrategy` 默认值 `'strategy1'` 保证历史行为不变。
- 回滚：删除新增字段与分支即可恢复，无残留状态。

## Open Questions

- 暂不引入「金字塔/倒金字塔」等更多减仓比例，本次仅覆盖「整仓」与「分两次半仓」两种；后续若扩展可在 `gridStrategy` 枚举中增加选项。
