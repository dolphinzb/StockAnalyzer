## Context

`008-grid-trading` 已实现网格持仓/开仓的静态计算（`GridView.vue` + `electron/services/gridService.ts`），但仅是"现状对比目标"的快照计算，无法回答"这个网格策略在过去 N 年行情里能赚多少"。

本项目是 Windows 桌面 Electron 应用，历史行情存放在本地 SQLite（`kline_data` 表），由 `klineAPI.getKlineData` / `database.getKlineData` 提供日 K 查询（升序）。分红在现有系统中仅作为手动交易记录（`trade_record` 中 `DIVIDEND` 类型），`tradeService` 中按"每股股息 × 持股数量"建模——但 `kline_data` 本身不含分红字段，因此仿真需采用可配置的分红模型（用户可选输入每股年股息，或关闭分红）。

本次设计为新增一个"网格交易仿真"能力，复用现有数据、类型与 UI 风格，作为纯只读回测，不污染现有交易/资金库表。

## Goals / Non-Goals

**Goals:**
- 提供仿真参数表单：开始日期、股票代码、初始资金、网格上限、网格下限、网格间距（固定金额或百分比）、每格交易股数（可留空，留空时按「初始资金 ÷ 档位数 ÷ 触发价」自动估算）、手续费率（可选，默认万 2.5、最低 5 元）、分红模型（可选）。
- 基于 `kline_data` 历史日 K，逐日运行网格策略，生成买入/卖出操作记录（含价格、数量、手续费、现金、持仓变化）。
- 计算收益指标：期末总资产、总收益、总收益率、年化收益率（按交易日/自然年）、最大回撤、累计分红、交易笔数。
- 在仿真页面以表格 + 指标卡片展示结果，并支持重置。

**Non-Goals:**
- 不写入 `trade_record` / `transfer_record`，不影响真实账户与资金统计。
- 不做实盘/模拟盘下单，不做实时行情接入。
- 不引入新的数据库表或外部依赖。
- 不做多股票组合仿真（本期仅单只股票）。
- 不处理前复权与分红再投资的精细税务（采用简化模型）。

## Decisions

### D1. 仿真计算所在进程：渲染进程直接计算
复用 `klineAPI.getKlineData` 取全部历史日 K 到前端，仿真算法放在前端 `composables` 或新增 `electron/services` 纯函数中，**不新增 IPC 通道**。

- 备选：在主进程 `gridSimulationService.ts` 中计算并新增 `grid-sim:run` IPC。
- 选择理由：与 `008-grid-trading` "计算逻辑简单时在渲染进程完成" 的既有约定一致；历史日 K 数据量小（单只股票数千行），前端计算 < 100ms，避免新增 IPC 与类型桥接成本。
- 若后续数据量大，可在 `electron/services/gridSimulationService.ts` 提供同构纯函数，供主进程调用。

### D2. 网格信号生成模型（首版同时支持 fixed 与 percentage 两种间距）
以"网格上限 `upper`、下限 `lower`、间距 `spacing`、间距类型 `spacingType`"生成 N 个价格档位：

- `spacingType = 'fixed'`（等量网格）：`levels = [lower, lower+spacing, ..., upper]`，`spacing` 为固定金额。
- `spacingType = 'percentage'`（等比网格）：从 `lower` 起，每档 `level[i+1] = level[i] × (1 + spacing)`，直到不超过 `upper`；`spacing` 为比例（如 0.05 表示 5%）。

**K 线数据与复权方式**：首版使用**不复权**（`adjustType = ''`）日 K 数据。理由：网格上下限由用户按真实市价设置，不复权价（含分红除权跳变）与用户设档的刻度一致，买卖触发价位 = 真实成交价，自洽直观。

**除权影响处理**：首版**忽略除权影响**——不识别、不特殊处理除权跳变日，把除权导致的价格跳变（如 10 元分红后到 9 元）当作普通网格向下穿越处理。理由：最简单且无阈值识别的边界 bug；偏差仅在于未计入分红带来的可加仓现金（结果略保守），但触发点位与用户在软件中看不复权 K 线手动操作完全一致。后续若需更真实，可升级为"不复权 + 除权事件识别跳过触发 + 模拟分红现金"。

每日使用当日 `[low, high]` 判断是否穿越档位触发交易。采用**游标档位 + 虚拟卖出占位模型**：

- **游标（cursorIdx）**：记录「最近一次操作发生的档位下标」（含虚拟卖出）。所有买卖判定都相对游标档位的相邻档位进行，而非相对收盘价。
- **首日底仓**：首个交易日按首个收盘价**向上最近档位**（最小 `lv >= firstClose`）以该档位值建立底仓（如 4.32 → 4.4 买入），游标指向该档；高于上限则不建仓（游标置 -1 等待下跌），低于下限以最低档建仓。
- **上涨穿越（卖出）**：当日 `high` 触及/涨穿游标上一档 `levels[cursorIdx+1]` → 以该档位值「卖出」并游标上移一格：
  - 若当时**真实持仓 > 0**：实际卖出（现金增加、持仓清零），卖出股数 = 当前全部持仓；
  - 若当时**已空仓（持仓 = 0）**：记一笔**虚拟卖出（virtual）**仅用于占位——不影响现金与持仓，但把游标推进到该档，使后续反向穿越能正确触发真实买入。
- **下跌穿越（买入）**：当日 `low` 触及/跌穿游标下一档 `levels[cursorIdx-1]` → 以该档位值**真实买入**并游标下移一格（需现金充足；资金不足则停止当日穿越）。
- **单日两遍都跑（支持反向震荡）**：每个交易日按 `[low, high]` 连续穿越，**两遍都执行**：先沿主导方向单向推到尽头（单遍 while，不反复重入，故无死循环），再沿反方向单向推到尽头。主导方向由收盘价在当日区间的位置决定：当日区间中点 `mid=(low+high)/2`，`close >= mid`（偏涨）→ **先下后上**；`close < mid`（偏跌）→ **先上后下**。这样单日可同时发生买入与卖出，且游标终点落在与收盘同向的一侧（偏涨停高位、偏跌停低位）。
- **单日连续穿越多档**：每一遍都是单向 while，游标沿该方向逐格推进直到当日 `[low, high]` 内不再发生该方向穿越。
- **示例**（初始 4.4 买入，间距 0.2）：4.4 买→4.6 卖（真实）→4.8 涨穿但已空仓→记虚拟卖出 4.8→5.0 涨穿仍空仓→记虚拟卖出 5.0；随后跌回 4.8，因游标在 5.0、low 跌穿 4.8 → 以 4.8 真实买入；再跌回 4.6 → 以 4.6 真实买入。
- **成交价一律采用档位值**（限价单挂档位成交）；盘中 high/low 仅用于判定是否穿越该档。
- 买入股数 = `sharesPerGrid`（手动）或「初始资金 ÷ 档位数 ÷ 档位触发价」估算（null 时），均向下取整到 100 股；卖出股数取当前全部持仓。

- 备选（间距）：仅支持 fixed 一种（已否决，首版即支持 fixed + percentage 两种）。
- 选择理由（间距）：用户明确要求首版同时支持两种；等比网格对宽价格区间更自然，字段 `spacingType` 已预留，`fixed | percentage` 均实现。
- 备选（复权/除权）：前复权、或"不复权 + 除权跳变识别跳过"。
- 选择理由（复权/除权）：前复权会整体偏移档位刻度（不计分红现金时更失真）；除权识别需阈值/分红日历且易误判。首版选"不复权 + 忽略除权"最简洁自洽。

### D3. 分红模型（首版暂不实现，忽略分红）
- **首版决定：分红完全不考虑**——仿真不生成 `DIVIDEND` 记录、不增加现金、也不特殊处理除权跳变（见 D2）。
- 预留 `dividendPerShare` 字段（默认 0）在类型中保留，便于后续版本启用；当前算法忽略该字段。
- 理由：用户明确首版不做分红，降低首版复杂度；`kline_data` 本身也无分红字段。偏差：结果略偏保守（少算分红可加仓现金），但不虚高。

### D4. 费用与交易单位
- 最小交易单位 100 股（`MIN_TRADE_UNIT`），买入/卖出数量向下取整到 100。
- 手续费：`fee = max(commissionRate × amount, minFee)`，默认 `commissionRate=0.00025`、`minFee=5`，可配置；卖出另计印花税（默认 0.0005，A 股现状），可配置。

### D5. 收益指标计算
- 期末总资产 = 期末现金 + 期末持仓股数 × 期末收盘价。
- 总收益 = 期末总资产 − 初始资金。
- 总收益率 = 总收益 / 初始资金 × 100%。
- 年化收益率 = (1 + 总收益率)^(365 / 持有自然日数) − 1，**按自然日口径**（持有天数 = 期末日期 − 开始日期的日历天数，含周末/停牌日），UI 明确标注"按自然日计算"。
- 最大回撤 = max(峰值总资产 − 谷值总资产) / 峰值总资产 × 100%，逐日跟踪总资产曲线。

### D6. 类型与 API 扩展
- 在 `shared/types/index.ts` 新增：`GridSimulationInput`、`GridSimulationOperation`（单笔操作）、`GridSimulationResult`、`GridSimulationAPI`（如需 IPC）。本期纯前端计算，可仅在前端 `src/types.ts` 定义。
- `useNavigation` 的 `ViewId` 增加 `'grid-simulation'`，`SideNav` 增加入口，`App.vue` 注册 `GridSimulationView`。

## Risks / Trade-offs

- **[Risk] K 线数据缺失/不足** → 校验开始日期后存在足够 `kline_data`；不足时 `useToast` 提示"该股票历史数据不足"。
- **[Risk] 单日多档穿越导致成交失真** → 采用档位游标，每日最多按穿越的相邻档位成交一次（保守）；文档注明此为简化假设。
- **[Risk] 分红模型偏离真实** → 首版不做分红，无此风险；字段预留供后续启用。
- **[Risk] 年化口径歧义** → UI 明确标注"按自然日计算"（含周末/停牌日），避免与交易日口径混淆。
- **[Trade-off] 前端计算** → 数据量大时性能略逊于主进程，但本期单股场景可忽略；纯函数可迁移。

## Migration Plan

- 纯新增功能，无破坏性变更；通过 `SideNav` 新增入口逐步展示。
- 回滚：移除 `GridSimulationView` 注册与 `SideNav` 入口即可，不影响现有库表与功能。
