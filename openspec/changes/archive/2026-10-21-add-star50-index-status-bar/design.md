## Context

当前指数行情数据流：

1. 主进程 `electron/services/priceFetcher.ts` 在既有价格轮询中，将 `INDEX_CODES`（`['sh000001', 'sz399001']`）与自选股代码合并后一次性请求新浪行情接口，结果按 `INDEX_CODES` 过滤分离
2. `parseIndexData()` 解析为 `IndexData`（code/name/price/change/changePercent/direction/lastUpdate），经 `index:update` IPC 广播到渲染进程
3. 渲染进程 `src/composables/useIndexData.ts` 监听事件维护 `indexDataState`（含错误时保留上次成功数据的降级逻辑）
4. `src/components/IndexStatusBar.vue` 按硬编码代码（`sh000001`/`sz399001`）从 `indices` 数组中匹配渲染，布局为左右两个 `flex:1` 指数项 + 绝对定位的错误提示浮层

约束：
- 指数代码遵循「交易所前缀 + 6位代码」约定（新浪行情源），科创50对应 `sh000688`（用户提供的 `1B0688` 为外部系统编码，`0688` 主体一致）
- 状态栏固定高度 30px，字号使用 `clamp()` 自适应
- 不得改变轮询频率、IPC 协议与 `IndexData` 结构

## Goals / Non-Goals

**Goals:**
- 状态栏展示第三个指数：科创50（`sh000688`），视觉与交互完全复用现有指数项
- 布局扩展为左中右三等分，窄窗口下不换行、不溢出、不遮挡
- 错误提示浮层不遮挡任何指数项内容
- 数据源层改动最小化：仅扩常量，不改解析、降级、广播逻辑

**Non-Goals:**
- 不新增用户自定义指数配置能力（指数清单仍为代码常量）
- 不引入指数 K 线/分时等富交互
- 不修改 `IndexData` 类型定义与 IPC 协议
- 不改变价格刷新频率与告警链路

## Decisions

### 决策 1：代码格式映射为 `sh000688`，不直接使用 `1B0688`

- **选择**：`INDEX_CODES` 增加 `'sh000688'`，`INDEX_NAMES['sh000688'] = '科创50'`
- **理由**：本应用所有指数代码（`sh000001`/`sz399001`）均遵循新浪行情源的「前缀+6位」约定，行情请求、结果过滤（`INDEX_CODES.includes(r.stockCode)`）、前端匹配全部基于此前缀格式。`1B0688` 是外部系统（券商终端等）编码，直接使用会导致请求与过滤链路失效
- **备选**：在前端做外部编码到内部编码的转换层——过度设计，单一指数无需引入映射表

### 决策 2：渲染层按代码匹配的 computed 模式水平扩展

- **选择**：在 `IndexStatusBar.vue` 中新增 `kc50Index` computed（`i.code === 'sh000688'`），模板复制现有指数项结构为中间项，保持与 `shIndex`/`szIndex` 完全一致的展示字段与样式类
- **理由**：与现有代码风格逐字一致，审阅成本最低；`indices` 数组本身已支持任意数量元素，无需改动数据层
- **备选**：抽象为 `v-for` 循环渲染指数列表——当前仅 3 个且各自位置语义固定（左中右），循环反而需要额外的顺序配置，暂不值得

### 决策 3：布局改为三等分，指数顺序为 上证（左）| 科创50（中）| 深成指（右）

- **选择**：三个 `.index-item` 均 `flex:1`，左项左对齐、右项右对齐、中间项居中，容器维持 `justify-content: space-between`
- **理由**：中间项天然利用 `space-between` 两侧空隙；三项等分在窄窗口下各自仍有一半以上可用宽度
- **备选**：科创50放右侧、深成指居中——无显著差异，按「沪→科创→深」的市场陈列顺序更直观

### 决策 4：错误提示浮层移至状态栏顶部外侧

- **选择**：`.error-indicator` 由 `left:50%` 居中浮层改为 `top: -20px; left: 50%; transform: translateX(-50%)`，悬浮于状态栏上沿之外
- **理由**：现状两项布局时浮层恰好落在中央空隙，不遮挡内容；新增中间指数项后，居中原位会直接遮挡科创50文字。移到上沿外侧彻底避免遮挡，且父容器 `.watchlist-view` 未设置 `overflow: hidden`，不会被裁剪
- **备选**：保持居中但提高 `z-index` 半透明覆盖——仍遮挡指数内容，不采用；移到右下角——偏离用户对错误提示的视觉焦点

## Risks / Trade-offs

- [窄窗口下三指数文字溢出] → 字号已使用 `clamp()`；名称/数值均为短文本，验证最小窗口宽度即可；如溢出优先缩减 `.index-change-percent` 显示（-- 占位逻辑已存在）
- [外部编码 `1B0688` 与 `sh000688` 映射错误导致取数失败] → `parseIndexData` 对 `result.success === false` 的指数会跳过并回退上次成功数据，前端显示 `--` 占位，不会崩溃；联调时以实际返回名称校验（应为「科创50」）
- [错误浮层外移后与上方内容重叠] → 浮层带不透明橙底，仅错误态出现；状态栏位于页面最底部，上方为股票列表，可接受
- [新浪行情源对 `sh000688` 返回异常（如停牌日字段缺失）] → 复用既有 `price <= 0` 校验分支，失败即跳过并走降级，无新增代码路径
