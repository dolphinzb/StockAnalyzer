# Feature Specification: 自选股K线数据下载功能

**Feature Branch**: `015-kline-download`  
**Created**: 2026-05-08  
**Status**: Draft  
**Input**: User description: "增加自选股K线数据下载功能：手动下载K线数据，在自选股列表中操作列增加下载历史K线按钮，点击后弹出日期选择框，选择时间段确定后下载指定时间段内的K线数据，完成后给出下载结果提示；自动下载当日K线数据，交易日15:10自动下载所有自选股的当日K线数据，非交易日不下载，完成后记录结果到日志文件中；要求MUST使用stock-sdk库；所有自选股的K线数据保存在同一张表中；K线数据为不复权的原始数据"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手动下载历史K线数据 (Priority: P1)

用户在自选股列表中，对某只股票点击"下载K线"按钮，弹出日期选择框，选择起止日期后点击确定，系统下载该股票在指定时间段内的日K线数据（不复权原始数据），下载完成后弹出结果提示（成功/失败/部分成功），告知用户下载的数据条数。

**Why this priority**: 手动下载是用户最直接的需求，允许用户按需获取任意时间段的历史K线数据，是K线数据功能的基础入口。

**Independent Test**: 在自选股列表中选择一只股票，点击下载K线按钮，选择日期范围后确认，验证数据是否正确下载并保存到数据库，且结果提示正确显示。

**Acceptance Scenarios**:

1. **Given** 用户在自选股列表页面，**When** 点击某只股票操作列的"下载K线"按钮，**Then** 弹出日期选择对话框，包含开始日期（默认1个月前）和结束日期（默认前一天）的输入控件，以及"确定"和"取消"按钮
2. **Given** 日期选择对话框已打开，**When** 用户选择有效的起止日期并点击"确定"，**Then** 对话框关闭，系统开始下载该股票在指定时间段内的日K线数据，下载过程中按钮显示加载状态
3. **Given** K线数据下载完成，**When** 下载成功，**Then** 弹出成功提示，显示"下载完成，共获取 N 条K线数据"，数据保存到数据库中
4. **Given** K线数据下载完成，**When** 下载部分成功（部分日期无数据），**Then** 弹出提示，显示"下载完成，共获取 N 条K线数据（部分日期无数据）"
5. **Given** K线数据下载完成，**When** 下载失败，**Then** 弹出错误提示，显示失败原因
6. **Given** 日期选择对话框已打开，**When** 用户选择开始日期晚于结束日期，**Then** 日期选择框显示验证错误提示，不允许提交
7. **Given** 正在下载K线数据，**When** 用户再次点击同一股票的"下载K线"按钮，**Then** 按钮保持禁用状态，防止重复下载
8. **Given** 指定时间段内已有该股票的K线数据，**When** 用户再次下载同一时间段的数据，**Then** 系统用新数据覆盖已有数据（按日期去重，保留最新数据）

---

### User Story 2 - 自动下载当日K线数据 (Priority: P1)

在每个交易日15:10，系统自动下载所有自选股的当日日K线数据（不复权原始数据），非交易日不执行下载。下载完成后，将结果记录到日志文件中，包括成功下载的股票数量、失败的股票及失败原因。

**Why this priority**: 自动下载确保用户无需手动操作即可持续积累K线数据，是数据完整性的保障，与手动下载同等重要。

**Independent Test**: 在交易日15:10前后观察系统是否自动触发下载，检查日志文件中是否记录了下载结果；在非交易日验证系统不执行下载。

**Acceptance Scenarios**:

1. **Given** 当前为交易日且时间为15:10，**When** 系统定时器触发，**Then** 自动下载所有自选股的当日日K线数据
2. **Given** 当前为非交易日（周末或法定节假日），**When** 系统定时器触发，**Then** 不执行下载操作，日志中记录"非交易日，跳过K线数据下载"
3. **Given** 自动下载完成，**When** 所有股票下载成功，**Then** 日志中记录"K线数据自动下载完成，共 N 只股票，全部成功"
4. **Given** 自动下载完成，**When** 部分股票下载失败，**Then** 日志中记录"K线数据自动下载完成，共 N 只股票，M 只成功，K 只失败"，并列出失败股票代码及失败原因
5. **Given** 自动下载中某只股票首次下载失败，**When** 系统自动重试1次，**Then** 若重试成功则视为成功，若仍失败则记录为失败
6. **Given** 自选股列表为空，**When** 系统定时器触发，**Then** 日志中记录"自选股列表为空，跳过K线数据下载"
7. **Given** 自动下载正在执行，**When** 用户同时触发手动下载，**Then** 手动下载正常执行，不受自动下载影响

---

### User Story 3 - 下载进度与结果反馈 (Priority: P2)

用户在手动下载K线数据时，能够看到下载进度（如"正在下载 3/10"），下载完成后收到明确的结果反馈。

**Why this priority**: 进度反馈提升用户体验，避免用户在长时间下载时不确定系统是否在工作，但属于增强功能。

**Independent Test**: 选择一只股票下载较长时间段的K线数据，验证进度提示是否正确更新，完成后结果提示是否准确。

**Acceptance Scenarios**:

1. **Given** 用户已触发K线数据下载，**When** 下载正在进行，**Then** 在操作列或弹窗中显示下载进度（如"正在下载..."或进度百分比）
2. **Given** 下载完成，**When** 结果为成功或部分成功，**Then** 使用Toast通知显示结果摘要，通知在3秒后自动消失
3. **Given** 下载完成，**When** 结果为失败，**Then** 使用Toast通知显示失败原因，通知需用户手动关闭

---

### Edge Cases

- 当stock-sdk请求超时或网络异常时，系统应捕获错误并提示用户，不影响其他股票的下载
- 当用户选择的日期范围超出stock-sdk支持的范围时，系统应返回实际可获取的数据并提示用户
- 当数据库写入失败时，系统应回滚事务并提示用户下载失败
- 当自选股列表中包含非A股股票代码时，系统应跳过该股票并在结果中标注"不支持的股票类型"
- 当自动下载与手动下载同时操作同一只股票时，以最后写入的数据为准（后写入覆盖先写入）
- 当stock-sdk返回的K线数据字段缺失时，系统应使用默认值（如成交量为0）并记录警告日志

## Clarifications

### Session 2026-05-08

- Q: K线数据的周期类型 → A: 仅支持日K线（历史K线），暂不支持周K、月K或分钟K线
- Q: 自动下载是否需要判断交易日 → A: 是，使用stock-sdk获取市场状态或通过日期判断（周末及法定节假日不下载）
- Q: 已有数据的覆盖策略 → A: 按股票代码+日期去重，新数据覆盖旧数据（UPSERT语义）
- Q: 自动下载失败后的重试策略 → A: 自动重试1次，若仍失败则记录日志，不再重试
- Q: 是否支持批量手动下载所有自选股K线 → A: 不支持，仅保留单只股票手动下载，全量下载由自动下载功能覆盖
- Q: 应用启动时是否需要补执行自动下载 → A: 不需要，删除启动补执行逻辑，自动下载仅在定时器触发时执行
- Q: 自动下载的请求并发策略 → A: 串行逐只下载，每只股票下载完成后再下载下一只，避免触发API限流
- Q: 手动下载日期选择框的默认日期范围 → A: 开始日期默认为1个月前，结束日期默认为前一天（当日K线可能未完成）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在自选股列表的操作列中增加"下载K线"按钮，每只股票一行一个按钮
- **FR-001a**: 系统 MUST NOT 提供批量下载所有自选股K线数据的手动入口，全量下载仅通过自动下载功能实现
- **FR-002**: 系统 MUST 在用户点击"下载K线"按钮后弹出日期选择对话框，包含开始日期和结束日期输入控件
- **FR-002a**: 日期选择对话框 MUST 默认开始日期为1个月前、结束日期为前一天，用户可修改
- **FR-003**: 系统 MUST 验证日期范围的有效性：开始日期不能晚于结束日期，结束日期不能晚于当前日期
- **FR-004**: 系统 MUST 使用 stock-sdk 库的 `getHistoryKline` 方法下载指定股票在指定时间段内的日K线数据，参数为不复权（fqType为空或不复权选项）
- **FR-005**: 系统 MUST 将下载的K线数据保存到数据库的同一张表中，表结构包含：唯一标识符、股票代码、日期、开盘价、最高价、最低价、收盘价、成交量、成交额、振幅、涨跌幅、涨跌额、换手率、创建时间、更新时间
- **FR-006**: 系统 MUST 对K线数据按股票代码+日期进行去重，已有数据使用新数据覆盖（UPSERT语义）
- **FR-007**: 系统 MUST 在手动下载完成后弹出结果提示，包括成功获取的数据条数或失败原因
- **FR-008**: 系统 MUST 在交易日15:10自动下载所有自选股的当日日K线数据（不复权原始数据）
- **FR-008a**: 系统 MUST 在自动下载时采用串行逐只下载策略，每只股票下载完成后再下载下一只，避免触发API限流
- **FR-009**: 系统 MUST 在非交易日（周末及法定节假日）不执行自动下载，并在日志中记录跳过原因
- **FR-010**: 系统 MUST 在自动下载完成后将结果记录到日志文件中，包括成功数量、失败数量及失败原因
- **FR-010a**: 系统 MUST 在自动下载失败时自动重试1次，若重试仍失败则记录日志，不再继续重试
- **FR-011**: 系统 MUST 在下载过程中显示加载状态，防止用户重复触发同一股票的下载
- **FR-012**: 系统 MUST 在stock-sdk请求失败时捕获异常，返回友好的错误提示，不影响其他股票的下载
- **FR-013**: 系统 MUST 仅支持A股股票的K线数据下载，对于非A股代码应跳过并在结果中标注
- **FR-014**: 系统 MUST 确保K线数据为不复权的原始数据，不进行前复权或后复权处理

### Key Entities *(include if feature involves data)*

- **K线数据(KlineData)**: 代表一只股票某一天的日K线数据，包含以下属性：唯一标识符、股票代码（与自选股表中的stock_code一致）、日期（交易日期）、开盘价、最高价、最低价、收盘价、成交量、成交额、振幅、涨跌幅、涨跌额、换手率、创建时间、更新时间。所有自选股的K线数据存储在同一张表中，通过股票代码区分不同股票。
- **下载任务(DownloadTask)**: 代表一次K线数据下载操作的上下文信息，包含：股票代码、开始日期、结束日期、下载状态（进行中/成功/失败/部分成功）、成功条数、失败原因。此实体为运行时状态，不需要持久化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在3次点击内完成一只股票的K线数据下载（点击按钮 → 选择日期 → 确认）
- **SC-002**: 单只股票单次下载1年内的K线数据在10秒内完成
- **SC-003**: 自动下载所有自选股（50只以内）的当日K线数据在60秒内完成
- **SC-004**: 下载的K线数据与stock-sdk返回的原始数据完全一致，无数据丢失或转换错误
- **SC-005**: 下载失败时100%给出明确的错误提示，不出现无响应或静默失败
- **SC-006**: 自动下载结果100%记录到日志文件中，可追溯

## Assumptions

- stock-sdk库已通过npm安装并可在Electron主进程中正常使用
- 自选股列表中的股票代码格式与stock-sdk要求的格式兼容（需要添加sh/sz前缀）
- stock-sdk的`getHistoryKline`方法支持不复权参数，返回原始K线数据
- 交易日判断可通过stock-sdk的市场状态接口或简单的日期规则（周末排除）实现，法定节假日暂通过简单规则处理
- K线数据表中的股票代码与自选股表中的stock_code字段格式一致（不含前缀的纯数字代码）
- 自动下载的定时任务在Electron主进程中运行，不依赖渲染进程
- K线数据的日期字段为交易日期（非自然日），stock-sdk返回的数据已排除非交易日
