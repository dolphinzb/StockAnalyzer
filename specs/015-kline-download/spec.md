# Feature Specification: 自选股K线数据下载功能（含前复权支持）

**Feature Branch**: `015-kline-download`  
**Created**: 2026-05-08  
**Updated**: 2026-05-11  
**Status**: Draft  
**Input**: User description: "扩展K线下载功能，增加前复权数据下载和存储能力：手动下载时同时下载不复权和前复权两种数据；自动下载时也下载两种复权类型；数据库增加adjust_type字段区分复权类型；K线弹窗完全依赖本地数据库数据，不再实时获取"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手动下载历史K线数据（含前复权） (Priority: P1)

用户在自选股列表中，对某只股票点击"下载K线"按钮，弹出日期选择框，选择起止日期后点击确定，系统同时下载该股票在指定时间段内的日K线数据（包括不复权和前复权两种类型），下载完成后弹出结果提示，分别显示两种复权类型的下载成功条数。

**Why this priority**: 手动下载是用户最直接的需求，同时下载两种复权类型避免用户重复操作，提升用户体验。

**Independent Test**: 在自选股列表中选择一只股票，点击下载K线按钮，选择日期范围后确认，验证数据库中是否同时存在不复权和前复权两种数据，且结果提示正确显示两种类型的数据条数。

**Acceptance Scenarios**:

1. **Given** 用户在自选股列表页面，**When** 点击某只股票操作列的"下载K线"按钮，**Then** 弹出日期选择对话框，包含开始日期（默认1个月前）和结束日期（默认前一天）的输入控件，以及"确定"和"取消"按钮
2. **Given** 日期选择对话框已打开，**When** 用户选择有效的起止日期并点击"确定"，**Then** 对话框关闭，系统开始同时下载该股票的不复权和前复权两种日K线数据，下载过程中按钮显示加载状态
3. **Given** K线数据下载完成，**When** 两种复权类型都下载成功，**Then** 弹出成功提示，显示"下载完成，共获取 N 条不复权数据，M 条前复权数据"，数据保存到数据库中
4. **Given** K线数据下载完成，**When** 仅一种复权类型下载成功，另一种失败，**Then** 弹出提示，显示"下载完成，不复权：N 条成功，前复权：下载失败（原因：XXX）"或相反
5. **Given** K线数据下载完成，**When** 两种复权类型都下载失败，**Then** 弹出错误提示，显示失败原因
6. **Given** 日期选择对话框已打开，**When** 用户选择开始日期晚于结束日期，**Then** 日期选择框显示验证错误提示，不允许提交
7. **Given** 正在下载K线数据，**When** 用户再次点击同一股票的"下载K线"按钮，**Then** 按钮保持禁用状态，防止重复下载
8. **Given** 指定时间段内已有该股票的某种复权类型数据，**When** 用户再次下载同一时间段的数据，**Then** 系统用新数据覆盖已有数据（按日期+复权类型去重，保留最新数据）

### User Story 2 - 自动下载当日K线数据（含前复权） (Priority: P1)

在每个交易日15:10，系统自动下载所有自选股的当日日K线数据（包括不复权和前复权两种类型），非交易日不执行下载。下载采用串行策略（股票A不复权→股票A前复权→股票B不复权→股票B前复权...）。下载完成后，将结果记录到日志文件中，分别统计两种复权类型的成功/失败数量。

**Why this priority**: 自动下载确保用户无需手动操作即可持续积累两种复权类型的K线数据，是数据完整性的保障。

**Independent Test**: 在交易日15:10前后观察系统是否自动触发下载，检查日志文件中是否分别记录了不复权和前复权的下载结果；在非交易日验证系统不执行下载。

**Acceptance Scenarios**:

1. **Given** 当前为交易日且时间为15:10，**When** 系统定时器触发，**Then** 自动串行下载所有自选股的当日不复权和前复权两种日K线数据
2. **Given** 当前为非交易日（周末或法定节假日），**When** 系统定时器触发，**Then** 不执行下载操作，日志中记录"非交易日，跳过K线数据下载"
3. **Given** 自动下载完成，**When** 所有股票两种复权类型都下载成功，**Then** 日志中记录"K线数据自动下载完成，共 N 只股票，不复权：N 只成功/0 只失败，前复权：N 只成功/0 只失败"
4. **Given** 自动下载完成，**When** 部分股票或部分复权类型下载失败，**Then** 日志中记录"K线数据自动下载完成，共 N 只股票，不复权：M 只成功/K 只失败，前复权：P 只成功/Q 只失败"，并列出失败详情
5. **Given** 自动下载中某只股票的某种复权类型首次下载失败，**When** 系统自动重试1次，**Then** 若重试成功则视为成功，若仍失败则记录为失败
6. **Given** 自选股列表为空，**When** 系统定时器触发，**Then** 日志中记录"自选股列表为空，跳过K线数据下载"
7. **Given** 自动下载正在执行，**When** 用户同时触发手动下载，**Then** 手动下载正常执行，不受自动下载影响
8. **Given** 自动下载正在执行，**When** 网络中断，**Then** 已完成的股票数据保留，未完成的记录失败，不整体回滚

### User Story 3 - K线弹窗展示（完全依赖本地数据） (Priority: P1)

用户在自选股列表中，点击某只股票的名称，弹出K线弹窗。弹窗首先从数据库查询对应复权类型的K线数据，若数据库中存在该复权类型数据，直接使用本地数据渲染；若数据库中无该复权类型数据，显示明确的提示信息。用户切换复权方式时，同样先查询数据库，若无数据则显示提示并保持当前视图不变。

**Why this priority**: K线图完全依赖本地缓存数据，提升响应速度，减少网络请求，是用户体验的核心改进。

**Independent Test**: 在自选股列表中点击一只已有K线数据的股票名称，验证K线弹窗是否正确从数据库加载数据并展示；删除数据库中某复权类型数据后，验证弹窗是否显示正确的提示信息。

**Acceptance Scenarios**:

1. **Given** 用户在自选股列表页面，**When** 点击某只股票的名称，**Then** 弹出K线弹窗，首先从数据库查询该股票的前复权K线数据（默认复权方式）
2. **Given** K线弹窗已打开，**When** 数据库中存在该股票的前复权K线数据，**Then** K线图正确展示所有日K线蜡烛图及成交量，1秒内完成渲染（100条以内）
3. **Given** K线弹窗已打开，**When** 数据库中无该股票的前复权K线数据，**Then** 弹窗中显示"暂无前复权数据，请先下载"的提示，不提供切换按钮
4. **Given** K线弹窗已打开且显示前复权数据，**When** 用户切换为"不复权"，**Then** 系统从数据库查询不复权K线数据
5. **Given** 用户切换复权方式，**When** 数据库中存在目标复权类型数据，**Then** K线图重新渲染为目标复权类型数据
6. **Given** 用户切换复权方式，**When** 数据库中无目标复权类型数据，**Then** 弹窗显示"暂无不复权数据，请先下载"或"暂无前复权数据，请先下载"，并保持当前视图不变
7. **Given** K线弹窗中K线数据较多（超过弹窗可视区域），**When** 用户按住鼠标左键并左右拖动，**Then** K线图随鼠标移动，展示不同日期范围的数据
8. **Given** K线弹窗已打开，**When** 该股票在trade_record表中有交易记录，**Then** K线图上在对应交易日期的位置标注交易点：买入标注"B"，卖出标注"S"，分红标注"D"
9. **Given** K线弹窗已打开，**When** 用户点击弹窗的关闭按钮或点击弹窗外部区域，**Then** 弹窗关闭，回到自选股列表

### User Story 4 - 数据库迁移与兼容性 (Priority: P1)

系统提供数据库迁移脚本，安全地为现有kline_data表添加adjust_type字段，并为已有数据设置默认值。迁移脚本可重复执行，迁移前后应用均可正常运行，现有功能不受影响。

**Why this priority**: 数据库迁移是功能实现的基础，必须保证数据安全和向后兼容，是所有其他功能的前提条件。

**Independent Test**: 执行迁移脚本，验证adjust_type字段是否正确添加，已有数据是否设置为''（不复权），查询功能是否正常，应用是否可正常启动和使用。

**Acceptance Scenarios**:

1. **Given** 系统中已有不复权K线数据，**When** 执行数据库迁移脚本，**Then** kline_data表中成功添加adjust_type字段，已有记录的adjust_type值为''
2. **Given** 数据库迁移已完成，**When** 查询kline_data表，**Then** 联合唯一约束为UNIQUE(stock_code, trade_date, adjust_type)，复合索引idx_kline_data_stock_date_adjust已创建
3. **Given** 数据库迁移已完成，**When** 应用启动并使用现有功能，**Then** 所有功能正常运行，不受迁移影响
4. **Given** 数据库迁移脚本已执行过一次，**When** 再次执行迁移脚本，**Then** 脚本可重复执行，不报错，数据保持一致
5. **Given** 数据库迁移执行失败，**When** 脚本检测到错误，**Then** 显示明确的错误提示，并提供回滚机制或手动修复指导

---

### Edge Cases

- 当stock-sdk请求超时或网络异常时，系统应捕获错误并提示用户，不影响其他复权类型或其他股票的下载
- 当用户选择的日期范围超出stock-sdk支持的范围时，系统应返回实际可获取的数据并提示用户
- 当数据库写入失败时，系统应回滚事务并提示用户下载失败
- 当自选股列表中包含非A股股票代码时，系统应跳过该股票并在结果中标注“不支持的股票类型”
- 当自动下载与手动下载同时操作同一只股票的同一复权类型时，以最后写入的数据为准（后写入覆盖先写入）
- 当stock-sdk返回的K线数据字段缺失时，系统应使用默认值（如成交量为0）并记录警告日志
- 当K线弹窗中某交易日同时存在多笔交易记录时，应在K线图上标注所有交易点，避免重叠遮挡
- 当K线数据仅有1条记录时，K线图应正常渲染单根蜡烛图，拖动功能不可用但不应报错
- 当用户在K线弹窗中切换前复权时，若数据库中无除权除息数据，则前复权结果与不复权一致
- 当交易记录的日期在K线数据日期范围之外时，该交易点不在K线图上标注
- 当一种复权类型下载成功、另一种失败时，分别记录结果，不整体回滚
- 当stock-sdk不支持某股票的某种复权类型时，捕获错误并记录日志，继续处理其他数据
- 当用户在下载过程中关闭窗口，已保存的数据不回滚，未完成的部分记录失败
- 当数据库中部分日期有数据、部分日期无数据时，按日期去重后合并保存
- 当迁移脚本执行失败时，必须有明确的错误提示和回滚机制

## Clarifications

### Session 2026-05-08

- Q: K线数据的周期类型 → A: 仅支持日K线（历史K线），暂不支持周K、月K或分钟K线
- Q: 自动下载是否需要判断交易日 → A: 是，使用stock-sdk获取市场状态或通过日期判断（周末及法定节假日不下载）
- Q: 已有数据的覆盖策略 → A: 按股票代码+日期+复权类型去重，新数据覆盖旧数据（UPSERT语义）
- Q: 自动下载失败后的重试策略 → A: 每种复权类型独立自动重试1次，若仍失败则记录日志，不再重试
- Q: 是否支持批量手动下载所有自选股K线 → A: 不支持，仅保留单只股票手动下载，全量下载由自动下载功能覆盖
- Q: 应用启动时是否需要补执行自动下载 → A: 不需要，删除启动补执行逻辑，自动下载仅在定时器触发时执行
- Q: 自动下载的请求并发策略 → A: 串行逐只下载，每只股票的两种复权类型依次下载（不复权→前复权），再处理下一只股票，避免触发API限流
- Q: 手动下载日期选择框的默认日期范围 → A: 开始日期默认为1个月前，结束日期默认为前一天（当日K线可能未完成）

### Session 2026-05-11

- Q: 前复权数据是否需要单独存储 → A: 是，在kline_data表中增加adjust_type字段区分，不复权为''，前复权为'qfq'
- Q: K线弹窗是否还需要实时获取数据 → A: 否，完全依赖本地数据库数据，不再调用stock-sdk实时获取
- Q: 数据库迁移脚本存放位置 → A: 存放在项目sql文件夹下，文件名与spec文件夹名称一致（015-kline-download/migration.sql）
- Q: 手动下载时两种复权类型的下载顺序 → A: 可以并行或串行，但需保证原子性（一种失败不影响另一种）
- Q: 自动下载时间是否会延长 → A: 是，数据量翻倍，预计时间从60秒放宽至120秒（50只股票）
- Q: 单只股票手动下载时间要求 → A: 从10秒放宽至15秒（1年内两种复权数据）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在自选股列表的操作列中增加"下载K线"按钮，每只股票一行一个按钮
- **FR-001a**: 系统 MUST NOT 提供批量下载所有自选股K线数据的手动入口，全量下载仅通过自动下载功能实现
- **FR-002**: 系统 MUST 在用户点击"下载K线"按钮后弹出日期选择对话框，包含开始日期和结束日期输入控件
- **FR-002a**: 日期选择对话框 MUST 默认开始日期为1个月前、结束日期为前一天，用户可修改
- **FR-003**: 系统 MUST 验证日期范围的有效性：开始日期不能晚于结束日期，结束日期不能晚于当前日期
- **FR-004**: 系统 MUST 使用 stock-sdk 库的 `getHistoryKline` 方法下载指定股票在指定时间段内的日K线数据，同时下载不复权（adjust=''）和前复权（adjust='qfq'）两种类型
- **FR-005**: 系统 MUST 将下载的K线数据保存到数据库的同一张表中，表结构包含：唯一标识符、股票代码、日期、开盘价、最高价、最低价、收盘价、成交量、成交额、振幅、涨跌幅、涨跌额、换手率、复权类型（adjust_type）、创建时间、更新时间
- **FR-006**: 系统 MUST 对K线数据按股票代码+日期+复权类型进行去重，已有数据使用新数据覆盖（UPSERT语义）
- **FR-007**: 系统 MUST 在手动下载完成后弹出结果提示，分别显示不复权和前复权两种类型的成功获取数据条数或失败原因
- **FR-008**: 系统 MUST 在交易日15:10自动下载所有自选股的当日日K线数据（包括不复权和前复权两种类型）
- **FR-008a**: 系统 MUST 在自动下载时采用串行策略：每只股票依次下载不复权→前复权，再处理下一只股票，避免触发API限流
- **FR-009**: 系统 MUST 在非交易日（周末及法定节假日）不执行自动下载，并在日志中记录跳过原因
- **FR-010**: 系统 MUST 在自动下载完成后将结果记录到日志文件中，分别统计不复权和前复权的成功数量、失败数量及失败原因
- **FR-010a**: 系统 MUST 在自动下载失败时，每种复权类型独立自动重试1次，若重试仍失败则记录日志，不再继续重试
- **FR-011**: 系统 MUST 在下载过程中显示加载状态，防止用户重复触发同一股票的下载
- **FR-012**: 系统 MUST 在stock-sdk请求失败时捕获异常，返回友好的错误提示，不影响其他复权类型或其他股票的下载
- **FR-013**: 系统 MUST 仅支持A股股票的K线数据下载，对于非A股代码应跳过并在结果中标注
- **FR-014**: 系统 MUST 确保K线数据存储时明确标记复权类型，不复权为''，前复权为'qfq'
- **FR-015**: 系统 MUST 在用户点击自选股列表中的股票名称时弹出K线弹窗，展示该股票的日K线图
- **FR-016**: 系统 MUST 在K线弹窗中提供前复权和不复权两种复权方式的切换控件，默认为前复权
- **FR-017**: 系统 MUST 在K线弹窗中支持鼠标左右拖动，当K线数据超过可视区域时，用户可通过拖动查看不同日期范围的数据
- **FR-018**: 系统 MUST 在K线图上标注交易记录点：买入交易标注"B"，卖出交易标注"S"，分红交易标注"D"，交易数据来源于trade_record表
- **FR-019**: 系统 MUST 在用户将鼠标悬停在交易点标注上时，显示该交易的详细信息（交易类型、交易价格、交易数量、持仓数量）
- **FR-020**: 系统 MUST 在K线弹窗打开时，首先从数据库查询对应复权类型的K线数据
- **FR-020a**: 系统 MUST 在K线弹窗打开时，若数据库中无对应复权类型数据，显示“暂无XXX复权数据，请先下载”的提示（XXX为“前”或“不”）
- **FR-021**: 系统 MUST 在K线弹窗中同时展示K线蜡烛图和成交量柱状图
- **FR-022**: 系统 MUST 在用户切换复权方式时，从数据库查询目标复权类型的K线数据并重新渲染K线图
- **FR-022a**: 系统 MUST 在用户切换复权方式时，若数据库中无目标复权类型数据，显示相应提示并保持当前视图不变
- **FR-023**: 系统 MUST 在K线弹窗关闭时释放相关资源，不影响其他功能
- **FR-024**: 系统 MUST 提供数据库迁移脚本，为现有kline_data表添加adjust_type字段（TEXT类型，NOT NULL，DEFAULT ''）
- **FR-025**: 系统 MUST 在数据库迁移脚本中为已有记录设置adjust_type=''（不复权）
- **FR-026**: 系统 MUST 在数据库迁移脚本中删除原有UNIQUE(stock_code, trade_date)约束并重建为UNIQUE(stock_code, trade_date, adjust_type)
- **FR-027**: 系统 MUST 在数据库迁移脚本中创建新的复合索引idx_kline_data_stock_date_adjust ON kline_data(stock_code, trade_date, adjust_type)
- **FR-028**: 系统 MUST 确保数据库迁移脚本可重复执行（使用IF NOT EXISTS或类似机制）
- **FR-029**: 系统 MUST 在数据库迁移执行前后验证数据完整性，确保迁移安全
- **FR-030**: 系统 MUST 在数据库迁移失败时提供明确的错误提示和回滚机制

### Key Entities *(include if feature involves data)*

- **K线数据(KlineData)**: 代表一只股票某一天的日K线数据，包含以下属性：唯一标识符、股票代码（与自选股表中的stock_code一致）、日期（交易日期）、开盘价、最高价、最低价、收盘价、成交量、成交额、振幅、涨跌幅、涨跌额、换手率、复权类型（adjust_type：''表示不复权，'qfq'表示前复权）、创建时间、更新时间。所有自选股的K线数据存储在同一张表中，通过股票代码和复权类型区分不同数据。联合唯一约束为UNIQUE(stock_code, trade_date, adjust_type)。
- **下载任务(DownloadTask)**: 代表一次K线数据下载操作的上下文信息，包含：股票代码、开始日期、结束日期、下载状态（进行中/成功/失败/部分成功）、不复权成功条数、前复权成功条数、不复权失败原因、前复权失败原因。此实体为运行时状态，不需要持久化。
- **K线弹窗(KlineChart)**: 代表K线图弹窗的展示状态，包含：股票代码、股票名称、当前复权方式（不复权/前复权）、K线数据列表（从数据库加载）、交易记录列表、拖动偏移量。此实体为运行时状态，不需要持久化。
- **交易标注**: K线图上的交易点标注直接复用已有的 `TradeRecord` 实体（来源于trade_record表），TradeRecord中已包含标注所需的全部字段：tradeDate（日期匹配）、tradeType（BUY→B, SELL→S, DIVIDEND→D）、tradePrice/tradeCount/holdingCount（tooltip详情展示）。无需新建TradeMarker类型。

## Success Criteria *(mandatory)*

- **SC-009**: 单只股票手动下载1年内的两种复权数据在15秒内完成

## Assumptions

- stock-sdk库已通过npm安装并可在Electron主进程中正常使用
- stock-sdk的`getHistoryKline`方法支持adjust参数：''（不复权）和'qfq'（前复权）
- 自选股列表中的股票代码格式与stock-sdk要求的格式兼容（需要添加sh/sz前缀）
- 交易日判断可通过stock-sdk的市场状态接口或简单的日期规则（周末排除）实现，法定节假日暂通过简单规则处理
- K线数据表中的股票代码与自选股表中的stock_code字段格式一致（不含前缀的纯数字代码）
- 自动下载的定时任务在Electron主进程中运行，不依赖渲染进程
- K线数据的日期字段为交易日期（非自然日），stock-sdk返回的数据已排除非交易日
- trade_record表中的trade_date字段格式与kline_data表中的trade_date字段格式一致，可直接用于日期匹配
- trade_record表中的trade_type字段包含BUY、SELL、DIVIDEND三种类型，分别对应B、S、D标注
- 前复权计算由stock-sdk在服务端完成，客户端无需自行实现复权算法
- K线图渲染使用Canvas或SVG技术，具体选型在实现计划阶段确定
- 数据库使用SQLite，支持ALTER TABLE添加字段和重建索引
- 数据库迁移脚本在执行时会检查字段和索引是否已存在，确保可重复执行
- 手动下载时两种复权类型的下载可以并行或串行，但需保证一种失败不影响另一种
- 自动下载时必须串行执行，避免触发API限流
- 用户对下载时间延长的容忍度：手动下载从10秒放宽至15秒，自动下载从60秒放宽至120秒
