## Context

当前盈亏统计页面 (`ProfitStatistics.vue`) 使用 `DateRangePicker` 组件让用户手动选择日期范围。用户需要点击日期输入框,在日历中选择开始和结束日期,操作步骤较多。

现有的交互流程:
1. 用户点击"开始日期"或"结束日期"输入框
2. 在弹出的日历中选择日期
3. 点击"计算"按钮执行查询

对于常用的时间段(今年、去年等),用户每次都需要重复上述步骤,效率较低。

**技术栈**:
- Vue 3 Composition API
- TypeScript
- SCSS
- Pinia Store (fundManagement)

**约束条件**:
- 不改变现有的 DateRangePicker 组件功能
- 保持向后兼容,不影响现有用户操作习惯
- 快捷按钮应与现有 UI 风格保持一致

## Goals / Non-Goals

**Goals:**
- 提供三个快捷按钮:"今年"、"去年"、"去年开始"
- 点击快捷按钮后自动设置日期范围并触发计算
- 保持现有手动日期选择功能完全不变
- UI 简洁直观,与现有设计风格一致

**Non-Goals:**
- 不修改 DateRangePicker 组件的内部逻辑
- 不添加自定义时间段保存功能
- 不实现快捷键支持
- 不改变盈亏统计的计算逻辑

## Decisions

### Decision 1: 快捷按钮的放置位置

**选择**: 在 `query-bar` 中,DateRangePicker 之后、计算按钮之前插入快捷按钮组

**理由**:
- 符合从左到右的操作流程:选择日期 → 快捷设置 → 计算
- 视觉上与现有按钮形成连贯的操作区域
- 不会遮挡或干扰现有的日期选择器

**替代方案**:
- ❌ 放在 DateRangePicker 内部:会污染通用组件,降低复用性
- ❌ 放在计算按钮之后:不符合操作逻辑顺序
- ❌ 单独一行显示:占用过多垂直空间

### Decision 2: 快捷按钮的实现方式

**选择**: 在 ProfitStatistics.vue 中直接添加三个 `<button>` 元素,使用内联样式类

**理由**:
- 简单直接,无需创建新组件
- 易于维护和修改
- 与现有的 btn-calculate、btn-reset 按钮风格一致

**替代方案**:
- ❌ 创建独立的 DateShortcuts 组件:过度设计,这三个按钮只在当前页面使用
- ❌ 扩展 DateRangePicker 组件:违反单一职责原则,DateRangePicker 应保持通用性

### Decision 3: 日期计算逻辑的位置

**选择**: 在 ProfitStatistics.vue 的 `<script setup>` 中实现日期计算函数

**理由**:
- 日期计算逻辑简单,不需要复用
- 直接在组件中实现更直观,便于理解数据流
- 避免在 store 中添加与业务无关的工具函数

**替代方案**:
- ❌ 在 fundManagement store 中添加:store 应专注于数据管理,而非日期计算
- ❌ 创建独立的 utils/date.ts 文件:当前只有三个简单的日期计算,不值得抽象

### Decision 4: 点击快捷按钮后的行为

**选择**: 点击快捷按钮后,先更新日期范围,然后自动调用 `handleCalculate()` 执行计算

**理由**:
- 减少用户操作步骤,一键完成设置和查询
- 符合用户对"快捷"功能的预期
- 与现有的用户体验保持一致(修改日期后需手动点击计算)

**替代方案**:
- ❌ 只更新日期范围,不自动计算:用户仍需点击计算按钮,不够"快捷"
- ❌ 弹出确认对话框:增加额外步骤,违背快捷设计的初衷

### Decision 5: 快捷按钮的视觉样式

**选择**: 使用次要按钮样式(白色背景,灰色边框),类似现有的"重置"按钮

**理由**:
- 与"重置"按钮功能类似(都是辅助操作),视觉权重应该相当
- 不会抢夺主要操作("计算"按钮)的注意力
- 保持 UI 层次清晰:主要操作(蓝色) > 次要操作(白色)

**替代方案**:
- ❌ 使用与计算按钮相同的蓝色样式:会让用户困惑哪个是主要操作
- ❌ 使用链接样式:可点击性不够明显

## Risks / Trade-offs

### Risk 1: 按钮数量增多导致界面拥挤

**风险**: 在 query-bar 中添加三个按钮后,可能导致水平空间不足,特别是在小屏幕上

**缓解措施**:
- 使用紧凑的按钮文本("今年"、"去年"、"去年开始")
- 减小按钮之间的间距(gap)
- 使用 `white-space: nowrap` 防止文本换行
- 必要时可通过 CSS media query 在小屏幕上调整布局

### Risk 2: 用户可能不理解"去年开始"的含义

**风险**: "去年开始"这个表述可能不够直观,用户可能不清楚它的具体含义

**缓解措施**:
- 使用清晰的中文标签
- 可以考虑添加 tooltip 提示,鼠标悬停时显示具体日期范围
- 在首次使用时可以通过简短的说明文字引导用户

### Trade-off 1: 自动化 vs 可控性

**权衡**: 自动触发计算提升了便捷性,但失去了让用户先预览日期范围再决定是否计算的机会

**决策**: 选择便捷性优先,因为:
- 日期范围的变化是可见的(日期输入框会更新)
- 用户可以随时点击"重置"清除选择
- 计算操作的开销不大,即使误触也不会造成严重影响

### Trade-off 2: 硬编码 vs 配置化

**权衡**: 将快捷选项硬编码在组件中,而不是通过配置文件管理

**决策**: 选择硬编码,因为:
- 这三个选项是业界标准做法,不太可能频繁变更
- 配置化会增加复杂度,但收益有限
- 如果未来需要更多自定义选项,可以重构为配置驱动
