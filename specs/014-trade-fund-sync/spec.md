# Feature Specification: 交易记录新增时自动同步资金明细

**Feature Branch**: `014-trade-fund-sync`  
**Created**: 2026-05-07  
**Status**: Draft  
**Input**: 交易记录(trade_record)新增时自动同步到资金明细(transfer_records)表，包括买入自动创建STOCK_BUY、卖出自动创建STOCK_SELL和DIVIDEND_TAX(FIFO逐批计算)、股息自动创建DIVIDEND

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 买入股票时自动记录资金流出 (Priority: P1)

用户在持仓页面新增一笔买入交易记录时，系统自动在资金明细表中创建一条"股票买入(STOCK_BUY)"类型的资金流水，金额为买入金额+手续费，日期与交易日期一致。用户无需手动在资金明细页面重复录入。

**Why this priority**: 买入是最基本的交易操作，自动同步可以消除手动录入的遗漏和错误，是整个数据一致性的基础。

**Independent Test**: 在持仓页面新增一笔买入交易，然后切换到资金明细页面，验证是否自动出现一条STOCK_BUY类型的资金流水，金额和日期正确，账户余额正确减少。

**Acceptance Scenarios**:

1. **Given** 用户在持仓页面新增一笔买入交易(如买入1000股@5元), **When** 交易记录保存成功, **Then** 系统自动在资金明细表中创建一条STOCK_BUY类型的记录，金额为买入金额+手续费(如5000+15=5015元)，日期与交易日期一致，账户余额相应减少
2. **Given** 用户在持仓页面新增一笔买入交易, **When** 资金明细自动记录创建失败, **Then** 交易记录仍然保存成功，但系统通过Toast通知提示用户资金明细同步失败，建议手动补录

---

### User Story 2 - 卖出股票时自动记录资金流入和股息扣税 (Priority: P1)

用户在持仓页面新增一笔卖出交易记录时，系统自动在资金明细表中创建两条资金流水：(1)"股票卖出(STOCK_SELL)"类型，金额为卖出金额-手续费-印花税，日期与交易日期一致；(2)"股息扣税(DIVIDEND_TAX)"类型，金额按FIFO逐笔计算各买入批次的股息税之和，日期为卖出次日。如果所有批次均免税则不创建股息扣税记录。

**Why this priority**: 卖出涉及资金流入和股息税扣缴，是已实现盈亏计算的关键数据来源。

**Independent Test**: 在持仓页面新增一笔卖出交易，验证资金明细表中自动出现STOCK_SELL和DIVIDEND_TAX(如有)两条记录，金额、日期和账户余额正确。

**Acceptance Scenarios**:

1. **Given** 用户在持仓页面新增一笔卖出交易(如卖出1000股@8元), **When** 交易记录保存成功, **Then** 系统自动在资金明细表中创建一条STOCK_SELL类型的记录，金额为卖出金额-手续费-印花税(如8000-8-8=7984元)，日期与交易日期一致，账户余额相应增加
2. **Given** 用户卖出的股票在持股期间有过分红(如0.3元/股×1000股=300元), 且各买入批次按FIFO计算持股期限在1个月到1年之间(税率10%), **When** 交易记录保存成功, **Then** 系统额外在资金明细表中创建一条DIVIDEND_TAX类型的记录，金额为各批次股息税之和(如全部10%税率则300×10%=30元)，日期为卖出次日，账户余额相应减少
3. **Given** 用户卖出的股票在持股期间有过分红, 但所有买入批次持股均超过1年(免税), **When** 交易记录保存成功, **Then** 系统不创建DIVIDEND_TAX类型的记录
4. **Given** 用户卖出的股票在持股期间没有分红, **When** 交易记录保存成功, **Then** 系统不创建DIVIDEND_TAX类型的记录
5. **Given** 用户卖出的股票在持股期间有过分红, 且不同买入批次跨越税率临界点(如500股持仓55天税率10%，500股持仓10天税率20%), **When** 交易记录保存成功, **Then** 系统按FIFO逐批计算股息税并汇总(如0.3×500×10%+0.3×500×20%=15+30=45元)，创建一条DIVIDEND_TAX记录

---

### User Story 3 - 股息分红时自动记录资金流入 (Priority: P1)

用户在持仓页面新增一笔股息(DIVIDEND)类型的交易记录时，系统自动在资金明细表中创建一条"股息(DIVIDEND)"类型的资金流水，金额为股息总额(每股股息×持股数量)，日期与交易日期一致。

**Why this priority**: 股息是已实现收入的重要组成部分，自动同步确保资金明细完整。

**Independent Test**: 在持仓页面新增一笔股息交易，验证资金明细表中自动出现DIVIDEND类型的记录，金额和日期正确，账户余额正确增加。

**Acceptance Scenarios**:

1. **Given** 用户在持仓页面新增一笔股息交易(如0.3元/股×1000股=300元), **When** 交易记录保存成功, **Then** 系统自动在资金明细表中创建一条DIVIDEND类型的记录，金额为300元，日期与交易日期一致，账户余额相应增加

---

### Edge Cases

- 当交易记录同步到资金明细失败时，交易记录仍应保存成功，但需通过Toast通知提示用户手动补录
- 当卖出股票时持股期间有多次分红，股息扣税应按FIFO逐批计算：每个卖出批次独立匹配其持股期间的股息事件，分别计算税额后汇总
- 当持股期限刚好在税率临界点(如1个月或1年)，按较低税率计算(1个月按10%，1年按免税)
- 当不同买入批次跨越税率临界点时，各批次独立适用对应税率，汇总为一条DIVIDEND_TAX记录
- 当用户在资金明细页面手动添加了STOCK_BUY/STOCK_SELL/DIVIDEND/DIVIDEND_TAX类型的记录时，与自动同步创建的记录独立共存，不会被视为重复

## Clarifications

### Session 2026-05-07

- Q: 股息扣税的时机 → A: A股股息税在卖出时扣缴，不是分红时扣。卖出次日自动记录DIVIDEND_TAX
- Q: 持股期限如何计算 → A: 采用FIFO(先进先出)逐笔计算，将卖出数量按买入时间顺序拆分到各买入批次，每个批次独立计算持股时长和适用税率，汇总各批次股息税为一条DIVIDEND_TAX记录
- Q: 手动录入的资金明细与自动同步的记录冲突 → A: 允许共存，自动同步创建的记录与手动录入的记录独立存在，互不影响
- Q: 自动同步失败时如何提示用户 → A: 使用非阻塞式Toast通知，在页面右上角显示短暂的通知消息(自动消失)，不打断用户操作流程
- Q: 功能范围 → A: 本次仅实现新增交易记录时的自动同步，不包含修改/删除交易记录时的同步更新，也不包含盈利统计页面的重新设计

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在用户新增买入(BUY)交易记录时，自动在资金明细表中创建一条STOCK_BUY类型的记录，金额为买入金额+手续费，日期与交易日期一致
- **FR-002**: 系统 MUST 在用户新增卖出(SELL)交易记录时，自动在资金明细表中创建一条STOCK_SELL类型的记录，金额为卖出金额-手续费-印花税，日期与交易日期一致
- **FR-003**: 系统 MUST 在用户新增卖出(SELL)交易记录时，如果持股期间有分红且存在需扣税的买入批次，自动在资金明细表中创建一条DIVIDEND_TAX类型的记录，金额为FIFO各批次股息税之和，日期为卖出次日
- **FR-003a**: 持股期限税率：≤1个月20%，1个月~1年10%，>1年免税
- **FR-003b**: 持股期限 MUST 按FIFO(先进先出)逐笔计算：将卖出数量按买入时间顺序拆分到各买入批次，每个批次从其买入日期到卖出日期独立计算持股时长和适用税率
- **FR-003c**: 每个卖出批次 MUST 独立匹配其持股期间(买入日到卖出日)内的股息事件，按持股数量比例计算该批次对应的股息金额，再乘以适用税率得到该批次股息税
- **FR-003d**: 所有批次的股息税 MUST 汇总为一条DIVIDEND_TAX记录，而非每个批次单独创建
- **FR-004**: 系统 MUST 在用户新增股息(DIVIDEND)交易记录时，自动在资金明细表中创建一条DIVIDEND类型的记录，金额为股息总额(每股股息×持股数量)，日期与交易日期一致
- **FR-005**: 自动同步失败时 MUST NOT 阻止交易记录的保存，但 MUST 通过非阻塞式Toast通知(页面右上角短暂显示)提示用户同步失败，建议手动补录

### Key Entities *(include if feature involves data)*

- **资金明细记录(TransferRecord)**: 表结构不变，自动同步创建的记录与手动录入的记录使用相同的表结构，独立共存

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在持仓页面新增交易记录后，切换到资金明细页面能在2秒内看到对应的自动同步记录
- **SC-002**: 股息扣税的税率判断准确率100%，与A股FIFO规则完全一致
- **SC-003**: 自动同步失败时，交易记录仍能正常保存，不影响用户的核心操作流程
- **SC-004**: 买入同步的金额(含手续费)与手动计算结果100%一致

## Assumptions

- 手续费计算沿用现有tradeService.ts中的费率逻辑(万三佣金、最低5元、华泰其他费率等)
- 印花税计算沿用现有逻辑(卖出时千分之一)
- 持股期限采用FIFO(先进先出)逐笔计算：卖出时按买入时间顺序将卖出数量拆分到各买入批次，每个批次独立计算持股时长和适用税率，汇总各批次股息税为一条DIVIDEND_TAX记录
- 股息扣税日期为卖出次日(交易日)，如果次日为非交易日则顺延到下一个交易日
- 用户仍可在资金明细页面手动添加STOCK_BUY/STOCK_SELL/DIVIDEND/DIVIDEND_TAX类型的记录，与自动同步创建的记录独立共存
- 本次不处理修改/删除交易记录时的资金明细同步，后续版本再实现
- 本次不涉及盈利统计页面的重新设计
