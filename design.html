StockAnalyzer · 功能设计文档

基于 Electron + Vite + Vue 3 + TypeScript 的个人股票分析与持仓管理桌面应用

v0.x · 最后更新：2026-09-20（含 017 形态识别） · 已交付功能：17 个 change · 维护分支：main

1. 项目概述

1.1 背景与目标

StockAnalyzer 是一个面向个人投资者的桌面端股票辅助工具。它把"看行情、记交易、算盈亏、做网格"装进同一个不联网（或只在必要时联网）的本地应用里：行情数据通过国内财经 API（新浪/东方财富/腾讯）按轮询节奏拉取，交易记录、资金明细、K 线数据全部存在本地 SQLite，盈亏与网格交易计算在主进程内完成，渲染端只负责展示与交互。

1.2 目标用户

  • 个人投资者：管理几十只以内的自选股、记录日常买入卖出、定期复盘盈亏。
  • 量化爱好者：使用网格交易策略做机械化操作，希望可视化每个策略的当前价位与盈亏。
  • 技术型用户：要求"数据在我自己机器上"，不希望交易记录、持仓数据上传到任何第三方。

1.3 核心价值主张

本地优先

数据全部存在 sql.js（内存 SQLite 落盘），无任何远端数据库依赖。

类型安全

TypeScript 严格模式 + 共享类型层，主/渲染两端共用同一份契约。

可扩展

功能模块通过 OpenSpec 工作流逐个交付，每个 change 独立分支、独立归档。

1.4 术语表

术语 含义
自选股 用户主动加入监控列表的股票，可设买卖阈值、启停监控。
持仓 当前仍持有的股票及其数量与成本，由交易记录自动汇总。
历史交易 已清仓（买卖配对形成完整周期）的股票及其完整交易链。
网格交易 基于价格区间和等比/等差网格的机械化低买高卖策略。
资金明细 账户层面的转账/分红/利息等流水，影响账户余额。
K 线 日级 OHLCV 行情数据，支持前复权与不复权两种调整方式。
形态识别 （规划中）基于日 K 序列检测日本蜡烛图经典形态的能力。

3. 架构设计

3.2 IPC 通信契约

所有跨进程调用都通过 ipcMain.handle 注册为"请求-响应"模式；推送类通知（配置变更、刷新结果）走 webContents.send + preload 端订阅。命名风格：<domain>:<action>，例如 watchlist:add、kline:get-chart-data。

域 典型 IPC 方向 说明
watchlist watchlist:add / watchlist:update / watchlist:delete / watchlist:list 双向 自选股 CRUD
trade trade:add / trade:list / trade:by-stock 双向 交易记录 CRUD
position position:list / position:compute 双向 持仓聚合（从 trade_records 计算）
kline kline:download / kline:get-chart-data 双向 K线下载与图表数据查询
fund fund:list / fund:add / fund:delete 双向 资金明细
config config:get / config:set / config:onLoaded 双向 + 推送 应用配置
backup backup:run-now / backup:list 双向 手动备份
index index:status / index:onUpdate 双向 + 推送 大盘指数
安全红线 渲染进程禁止直接 require('fs') 或 require('electron')。所有文件系统、窗口、系统能力调用都必须经 IPC 转发，由 electron/index.ts 统一登记。

3.4 Pinia 状态管理

采用 Composition API 风格 defineStore，每个 store 内部使用 ref / computed / 函数三段式封装业务逻辑：

// src/stores/watchlist.ts（示意）
export const useWatchlistStore = defineStore('watchlist', () => {
  // ── 状态 ──
  const stocks = ref<WatchlistStock[]>([])
  const loading = ref(false)
  const error = ref<string | null>(null)

  // ── 计算 ──
  const enabledStocks = computed(() => stocks.value.filter(s => s.monitorEnabled))

  // ── 动作 ──
  async function refresh() {
    loading.value = true
    try { stocks.value = await window.api.watchlistList() }
    catch (e) { error.value = (e as Error).message }
    finally { loading.value = false }
  }

  return { stocks, loading, error, enabledStocks, refresh }
})

3.5 共享类型层

所有跨进程接口契约放 shared/types/index.ts，由主进程与渲染进程共同引用；tsconfig.json 在 include 中显式声明 shared/**，避免跨 tsconfig project 引用造成的类型丢失。

分组 代表类型
窗口/平台 WindowAPI、platform
配置 AppConfig、TradingConfig、PollingConfig、ApiConfig
业务实体 WatchlistStock、TradeRecord、FundDetailRecord、BackupFile
K线 KlineData、AdjustType
API 提供商 ApiProviderOption、API_PROVIDERS
形态识别 CandlestickPatternCode、PatternHit、TrendInfo、PatternContext、PatternDefinition

5.4 006 · 自选股页面

006 · Stock Watchlist Page

业务目标

用户添加关注的股票、查看实时价格、买卖阈值、涨跌幅；可启用/禁用监控。

核心业务规则

  • 买入价 < 卖出价（同只股票）由表单校验保证
  • 股票代码格式必须匹配 (sh|sz|hk)\d{6}
  • 监控列表按 monitor_enabled DESC, updated_at DESC 排序
  • 价格突破阈值时通过 alertService 触发系统通知

5.5 007 · 持仓页面

007 · Position Page

业务目标

从交易记录自动聚合当前持仓，展示成本、最新价、浮动盈亏。

核心业务规则

  • 持仓成本采用移动加权平均（sum(cost × qty) / sum(qty)，剔除卖出）
  • 盈亏 = (最新价 − 平均成本) × 持仓数量
  • 交易记录分页展示，单只可折叠展开
  • 支持 单只展开模式（同时只展开一只）

5.6 008 · 网格交易（策略配置）

008 · Grid Trading — Configuration

业务目标

配置网格策略的静态参数（价格区间、网格类型、每格手数），自动生成各档买卖价位清单。属于"配置 + 展示"，不涉及在历史 K 线上跑模拟。

核心业务规则

  • 等比网格：price[i] = priceMin × ratio^i，ratio = (priceMax / priceMin)^(1 / (gridCount - 1))
  • 等差网格：price[i] = priceMin + step × i，step = (priceMax - priceMin) / (gridCount - 1)
  • 档位清单：每档含触发方向（buy / sell）、触发价、建议手数（按可用资金均分，可手动覆盖）
  • 校验：priceMin < priceMax、gridCount ≥ 2、每格手数 × 价格 ≤ 可用资金
  • 持久化到 grid_strategies 表（specs/008 schema 范围内），不写交易记录、不写资金流水

非目标（明确排除）

  • 在历史 K 线上跑策略模拟——见 §5.7 网格交易仿真
  • 实时根据行情触发交易信号——见 008 告警 + 用户手动确认

5.7 008-sim · 网格交易仿真

008-sim · Grid Trading — Simulation

业务目标

把 §5.6 配置出来的网格策略，在历史 K 序列上回放一遍，产出"假如当时按此策略机械执行"的模拟成交与盈亏，帮助用户在投入真金白银前评估策略表现。

核心业务规则

  • 回放输入：一份网格策略（来自 §5.6）+ 一段时间窗口的日 K + 初始资金
  • 触发逻辑：按 K 线序列逐日判断，low ≤ price[i] ≤ high 即视为触发该档位；同一日多档同时满足时按最靠近当前价的优先级处理
  • 多策略内置：strategy1=半仓平衡、strategy2=阈值满仓、strategy3=再平衡偏差预警、strategy4=全部触发、strategy5=自定义（暴露前置策略参数）
  • 仿真输出：模拟交易记录列表、累计盈亏曲线、最大回撤、胜率、单笔平均收益
  • 仿真数据：仅渲染进程内计算，不写入 trade_records / transfer_records（与真实交易严格隔离）
  • 入口：useNavigation 中独立的 ViewId = 'grid-simulation'，对应独立页面 GridSimulationView.vue

非目标（明确排除）

  • 真实交易执行——本模块所有写入只停留在渲染端内存
  • 分钟级/盘中高频回放——只支持日 K 序列回放

009 · Log Viewer

5.9 010 · 指数状态栏

010 · Index Status Bar

业务目标

底部固定一行，展示主要大盘指数（沪深 300、创业板指等）的实时点位与涨跌幅。

关键设计

  • 轮询间隔与价格轮询一致（polling.interval）

5.10 011 · 历史交易

011 · Historical Trades

关键设计

  • 从 trade_records 中识别"已清仓"周期（BUY → SELL 配对直至 holdingCount = 0）
  • 支持 单只展开查看完整交易链
  • 显示每个周期的总盈亏、持仓天数、收益率

5.11 012 · 数据库备份

012 · Database Backup

关键设计

  • 自动备份：应用启动 + 每日定时，由 backupService.startBackupScheduler 调度
  • 手动备份：设置页面触发，调用 backup:run-now IPC
  • 备份文件命名：stockanalyzer-YYYYMMDD-HHmmss.db
  • 仅保留最近 N 个备份（默认 10），超出自动删除最旧

5.12 013 · 资金管理

013 · Fund Management

业务目标

记录资金明细（转入、转出、分红、利息等）并提供盈亏统计。

核心业务规则

  • account_balance 由每次资金操作后自动滚动计算
  • 资金类型枚举：IN / OUT / DIVIDEND / DIVIDEND_TAX / STOCK_BUY / STOCK_SELL / INTEREST
  • FIFO 原则扣除分红税（多次分红按先到先得）
  • 盈亏统计按已实现盈亏（已清仓）+ 浮动盈亏（持仓中）两段汇总

5.13 014 · 交易-资金同步

014 · Trade-Fund Sync

业务目标

保证 trade_records 与 transfer_records 一致性：新增买入自动生成 STOCK_BUY 资金流水、卖出生成 STOCK_SELL 流水、分红生成 DIVIDEND + DIVIDEND_TAX 流水。

核心业务规则

  • 同步发生在 service 层而非 DB 触发器，便于单测
  • 删除交易记录会同步删除其关联的资金流水
  • 修改交易数量/价格会反向调整对应流水金额

5.14 015 · K线下载

015 · K-line Download

业务目标

支持手动与自动下载指定股票的历史日 K 数据，写入 kline_data。

关键设计

  • adjust_type：qfq（前复权）/ none（不复权），两套数据并存

关键设计决策

  • 算法库下沉：32 个 PatternDefinition 以纯函数形式放在 shared/patterns/（按 single/double/triple 分目录），渲染端可直接 import，不依赖 fs 或 electron。
  • 三段式判定：每条形态以"几何阈值 + 趋势前提 + 强度评分"三段式定义；反转形态要求对立趋势、继续形态要求一致趋势，K 线 < 20 根 时一律返回 flat 趋势跳过判定。
  • 探测入口去重：detectPatterns(candles) 按 (code, endIndex) 去重，保留同一位置最强命中，避免重复绘制。
  • 页面与图表联动：新增 PatternScanView 页面（侧边栏"形态检测"入口），复用既有 useKlineChart 组件；点击列表行调用 scrollToIndex(endIndex) 居中图表并高亮命中点。
  • 标记图层隔离：useKlineChart.drawPatternMarkers(hits) 是独立绘制层，看涨 ▲ 绿 / 看跌 ▼ 红 / 转折 ◆ 黄，三色三形状且 Y 偏移错开，与既有 drawTradeMarkers（交易标记层）互不覆盖。
  • 类型共享：CandlestickPatternCode（32 个 string literal union）、PatternHit、TrendInfo、PatternContext、PatternDefinition 全部声明在 shared/types/index.ts。

核心业务规则

  • 选股范围：仅在用户自选股内选择；尚未下载 K 线的股票在选择器中禁用并提示"请先下载 K 线"。
  • 调整方式：默认 qfq（前复权），可切换为 none（不复权）；切换股票或调整方式都自动触发重新检测。
  • 日期窗口：默认"近 30 日"，可通过下拉切换预设档（近 30/60/90/180/365 日）或自定义。
  • 筛选维度：方向（全部/看涨/看跌/转折）、形态（32 选项 + 全部）、列表排序按强度默认 / 按日期可选，三者均为 computed 派生，不存储重复数据。
  • 空态分级：K 线 < 20 根 →"数据不足，无法检测"；无 K 线 → 列表禁用 + 提示下载；探测返回 [] →"近期未发现蜡烛图形态信号"；IPC 失败 → 复用既有 Toast。
  • 非目标（明确排除）：批量扫描全自选股、周线/分时形态、检测结果持久化、历史回测与胜率统计。

6. 核心业务规则与计算

6.1 持仓成本（加权平均法）

持仓成本不直接存储，由交易记录实时聚合：

avgCost = Σ(买入价格 × 买入数量 − 卖出对应成本)
         ─────────────────────────────────────────
                       当前持仓数量

其中"卖出对应成本"按先进先出或加权两种策略可选，本项目默认加权平均。

6.2 盈亏

类型 公式
浮动盈亏（未实现） (最新价 − 平均成本) × 持仓数量
已实现盈亏 Σ(卖出价 − 当时平均成本) × 卖出数量
含手续费净盈亏 已实现盈亏 − 累计手续费 − 分红税

6.3 网格策略核心公式

// 等比网格
ratio = (priceMax / priceMin)^(1 / (gridCount - 1))
price[i] = priceMin × ratio^i,  i = 0..gridCount-1

// 等差网格
step = (priceMax - priceMin) / (gridCount - 1)
price[i] = priceMin + step × i

// 每格手数（资金平均分配）
qtyPerGrid = floor(totalCapital / gridCount / price[i] / 100) × 100

6.4 资金统计月度聚合

对过去 60 个月的每月末日，按以下步骤聚合：

  1. 取该月及之前最近的 transfer_records.account_balance
  2. 取该月及之前最近的 trade_records.holding_count（每只股票）
  3. 取该月及之前最近的 kline_data.close（每只股票）
  4. 该月持仓市值 = Σ(close × holdingCount)
  5. 缺失月份用最近一个有效月份向前填充；完全无数据则该月不画点

6.5 形态识别判定（三段式）

每条形态的 PatternDefinition 由三段拼装，且由统一入口 detectPatterns(candles) 串联：

① 几何阈值

用百分比表示的 几何参数，与具体价格无关，便于跨品种迁移：

body = |close - open|
upperShadow = high - max(open, close)
lowerShadow = min(open, close) - low
range     = high - low
avgBody   = mean(body[i-1..i-N])

isDoji          ← body / range < 0.10
isLongLeggedDoji ← body / range < 0.10 AND upperShadow > range × 0.40 AND lowerShadow > range × 0.40
isHammer        ← lowerShadow > body × 2 AND upperShadow < body × 0.5 AND body < range × 0.40
... 32 个形态各自的阈值见 shared/patterns/{single,double,triple}/

② 趋势前提

反转形态要求"前 10 根与之对立"的趋势，继续形态要求"一致"；趋势由 MA5 / MA10 与 10 根收盘价动量共同刻画：

function trend(candles, endIndex): TrendInfo {
  if (endIndex < 20) return { direction: 'flat', slope: 0, strength: 0 }
  const closes = candles.slice(endIndex - 10, endIndex + 1).map(c => c.close)
  const ma5  = mean(closes.slice(-5))
  const ma10 = mean(closes)
  const momentum = (closes.at(-1) - closes[0]) / closes[0]    // 涨跌幅
  if (ma5 > ma10 && momentum > 0.01) return { direction: 'up',   ... }
  if (ma5 < ma10 && momentum < -0.01) return { direction: 'down', ... }
  return { direction: 'flat', ... }
}

判定时机：探测形态时取 形态结束根（endIndex）作为趋势计算的锚点。

③ 强度评分（0–100）

强度决定列表排序与前端高亮程度，由基础分 + 修饰分两部分组成：

维度 分值范围 判定依据
基础分 0–60 几何阈值匹配度（影线比例、实体大小）
趋势确认分 0–25 趋势越强且越符合形态方向，得分越高
位置加分 0–15 是否出现在关键支撑/阻力位附近

探测入口与去重

function detectPatterns(candles: Candle[]): PatternHit[] {
  const raw = REGISTRY.flatMap(def => def.detector(candles, def.code))
  // 同一位置同一形态只保留最强命中
  return dedupeBy(raw, hit => `${hit.code}@${hit.endIndex}`, (a, b) => b.strength - a.strength)
}
