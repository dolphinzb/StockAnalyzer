# Feature Specification: 资金管理功能

**Feature Branch**: `013-fund-management`  
**Created**: 2026-05-03  
**Status**: Draft  
**Input**: User description: "增加资金管理功能页面,包括两个tab页面:1、转账记录。支持列表查看,包括转账日期、金额、转账类型(转入/转出);支持新增、修改、删除转账记录 2、盈利统计。统计指定时间段内盈利。盈利=转出金额-转入金额+当前持仓金额。"

**Updated**: 2026-05-06 - 将转账记录功能升级为资金明细功能，扩展资金类型并增加账户余额自动计算功能

**Updated**: 2026-05-06 (Session 2) - 扩展资金类型至6种（增加股票买入/卖出），支持编辑时手动修改账户余额

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看和管理资金明细 (Priority: P1)

用户能够查看所有的资金明细记录,包括日期、金额、资金类型(转入/转出/股息/股息扣税/股票买入/股票卖出)和账户余额。用户可以新增资金明细记录、修改已有记录(包括手动修改账户余额)或删除不需要的记录。系统会自动计算每条记录的账户余额,但允许用户在编辑时手动调整。

**Why this priority**: 这是资金管理的基础功能,用户需要能够追踪资金的流入流出情况,是后续盈利统计的数据基础。

**Independent Test**: 可以通过添加几条资金明细记录并验证它们正确显示在列表中(包括自动计算的账户余额),然后测试编辑和删除功能来独立验证此功能。

**Acceptance Scenarios**:

1. **Given** 用户已打开资金管理页面并选择"资金明细"标签, **When** 页面加载完成, **Then** 显示所有历史资金明细记录的列表,包含日期、金额、类型和账户余额信息,且列表按日期倒序排列(最近的日期在上面)
2. **Given** 用户在资金明细列表页面, **When** 点击"新增记录"按钮并填写完整信息后保存, **Then** 新记录添加到列表中并正确显示,系统自动计算账户余额,且如果新记录日期较新则显示在列表顶部
3. **Given** 用户选中一条资金明细记录, **When** 点击"编辑"按钮并修改信息(包括可选的账户余额)后保存, **Then** 该记录的信息被更新并显示最新数据,如果用户修改了账户余额则使用用户输入的值,否则系统重新计算该记录及后续记录的账户余额,列表保持按日期倒序排列
4. **Given** 用户选中一条资金明细记录, **When** 点击"删除"按钮并确认操作, **Then** 该记录从列表中移除,系统重新计算后续记录的账户余额,剩余记录仍按日期倒序排列

---

### User Story 2 - 统计指定时间段内的盈利 (Priority: P2)

用户可以设置和修改账户余额（系统会持久化保存），并选择一个时间段查看盈利统计。盈利计算公式为:转出金额 + 账户余额 + 当前持仓金额 - 转入金额。

**Why this priority**: 盈利统计是资金管理的核心价值体现,帮助用户了解投资收益情况,但依赖于转账记录功能的完成。

**Independent Test**: 在已有转账记录和持仓数据的情况下,设置账户余额并选择不同时间段验证盈利计算结果的准确性。

**Acceptance Scenarios**:

1. **Given** 用户首次打开资金管理页面并选择"盈利统计"标签, **When** 页面加载完成, **Then** 自动统计历史所有转账记录及当前持仓,显示总体盈利情况,账户余额显示数据库中保存的值(首次使用默认为0)
2. **Given** 用户在盈利统计页面, **When** 修改账户余额并保存, **Then** 系统保存新的余额到数据库,并重新计算盈利统计
3. **Given** 用户在盈利统计页面已选择日期范围并显示结果, **When** 修改时间范围, **Then** 盈利数据实时更新以反映新的时间范围,账户余额保持不变
4. **Given** 用户选择的时间内没有任何转账记录, **When** 查看盈利统计, **Then** 显示盈利为账户余额+当前持仓金额(转入转出均为0)

---

### User Story 3 - 快速录入常用转账 (Priority: P3)

用户能够快速添加常见的转账类型(如初始投资、追加投资、部分提取等),减少手动输入的工作量。

**Why this priority**: 提升用户体验的增强功能,可以在核心功能完成后逐步完善。

**Independent Test**: 验证快捷转账模板是否正确填充表单字段,用户可以在此基础上进行修改并提交。

**Acceptance Scenarios**:

1. **Given** 用户在新增转账记录页面, **When** 选择一个预设的转账模板, **Then** 表单自动填充相应的转账类型和建议金额
2. **Given** 用户选择了转账模板, **When** 修改部分字段后保存, **Then** 记录按照用户最终填写的内容保存

---

### Edge Cases

- 当用户输入的金额为负数或零时,系统应拒绝保存并提示错误
- 当用户删除资金明细记录时,如果该记录影响盈利统计,应提示用户确认
- 当盈利统计的时间段内没有持仓数据时,系统应明确显示"无持仓数据"
- 当数据库中没有资金明细记录时,盈利统计应显示为零或提示信息
- 用户尝试编辑已被删除的记录时,系统应提示记录不存在
- 当实时查询持仓数据失败时,系统应显示错误提示并引导用户检查持仓系统状态
- 当新增第一条资金明细记录时,系统应根据初始账户余额(默认为0)和该笔金额计算账户余额
- 当编辑某条记录导致账户余额为负数时,系统应警告用户但允许保存(因为可能是合理的透支情况)

## Clarifications

### Session 2026-05-03

- Q: 转账类型的枚举值定义 → A: 仅使用"转入"和"转出"两种类型
- Q: 编辑和删除操作的UI交互方式 → A: 使用模态对话框进行编辑和删除确认
- Q: 新增转账记录的入口方式 → A: 页面顶部工具栏放置"新增转账"按钮
- Q: 盈利统计中"当前持仓金额"的获取方式 → A: 每次计算盈利时实时查询持仓系统获取最新数据
- Q: 转账记录列表的分页或滚动加载策略 → A: 无限滚动,初始加载20条

### Session 2026-05-06

- Q: 资金类型的枚举值定义 → A: 扩展为"转入(IN)"、"转出(OUT)"、"股息(DIVIDEND)"、"股息扣税(DIVIDEND_TAX)"四种类型
- Q: 账户余额的计算规则 → A: 根据上一条记录的账户余额结合本次金额自动计算。转入和股息增加余额,转出和股息扣税减少余额
- Q: 账户余额的持久化方式 → A: 每条资金明细记录都存储其对应的账户余额字段,编辑记录时需重新计算该记录及后续所有记录的账户余额
- Q: 是否支持手动修改账户余额 → A: 支持,在盈利统计页面可以手动修改账户余额,修改后会保存到数据库并重新计算盈利统计

### Session 2026-05-06 (Session 2)

- Q: 是否需要增加股票相关的资金类型 → A: 是,增加"股票买入(STOCK_BUY)"和"股票卖出(STOCK_SELL)"两种类型。股票买入表示资金离开账户(减少余额),股票卖出表示资金进入账户(增加余额)
- Q: 编辑资金明细时是否允许修改账户余额 → A: 是,在编辑对话框中增加账户余额输入框,用户可以选择使用自动计算的值或手动输入自定义值。如果用户手动修改了账户余额,则使用该值;否则系统自动计算

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供资金管理页面,包含"资金明细"和"盈利统计"两个标签页
- **FR-002**: 系统 MUST 在资金明细标签页中显示所有资金明细记录的列表,包含日期、金额、资金类型(转入/转出/股息/股息扣税/股票买入/股票卖出)和账户余额五个字段
- **FR-002a**: 当用户首次进入资金明细标签页时,系统 MUST 默认显示所有历史资金明细记录,不进行日期过滤
- **FR-002b**: 资金类型 MUST 包含"转入(IN)"、"转出(OUT)"、"股息(DIVIDEND)"、"股息扣税(DIVIDEND_TAX)"、"股票买入(STOCK_BUY)"、"股票卖出(STOCK_SELL)"六种枚举值。转入、股息和股票卖出表示资金进入账户(增加余额),转出、股息扣税和股票买入表示资金离开账户(减少余额)
- **FR-002c**: 资金明细列表页面 MUST 在顶部工具栏提供"新增记录"按钮作为主要入口
- **FR-003**: 系统 MUST 允许用户新增资金明细记录,包括选择资金类型、输入金额和日期
- **FR-003a**: 当用户新增资金明细记录时,系统 MUST 根据上一条记录的账户余额和本笔金额自动计算并保存本条记录的账户余额
- **FR-004**: 系统 MUST 允许用户修改已有的资金明细记录的所有字段(包括可选的账户余额),通过模态对话框进行编辑
- **FR-004a**: 当用户编辑资金明细记录时,如果用户手动修改了账户余额,系统 MUST 使用用户输入的值;否则系统 MUST 重新计算该记录及后续所有记录的账户余额并更新到数据库
- **FR-005**: 系统 MUST 允许用户删除资金明细记录,并在删除前通过模态对话框要求用户确认
- **FR-005a**: 当用户删除资金明细记录时,系统 MUST 重新计算后续所有记录的账户余额并更新到数据库
- **FR-006**: 系统 MUST 在盈利统计标签页中提供日期范围选择器和账户余额显示/编辑功能,允许用户设置开始日期、结束日期和查看/修改当前账户余额
- **FR-006a**: 当用户首次进入盈利统计标签页时,系统 MUST 从数据库读取保存的账户余额,自动计算并显示历史所有转账记录的盈利统计
- **FR-006b**: 系统 MUST 提供修改账户余额的功能,用户修改后保存到数据库
- **FR-007**: 系统 MUST 根据公式"盈利 = 转出金额 + 账户余额 + 当前持仓金额 - 转入金额"计算指定时间段内的盈利
- **FR-008**: 系统 MUST 实时显示盈利统计结果,包括转出总额、转入总额、账户余额、当前持仓金额和最终盈利
- **FR-009**: 系统 MUST 验证金额必须为正数,否则拒绝保存并提示错误
- **FR-010**: 系统 MUST 持久化存储所有资金明细记录到数据库中,包括每条记录对应的账户余额
- **FR-010a**: 系统 MUST 在数据库中为资金明细记录表增加account_balance字段,用于存储每条记录计算后的账户余额
- **FR-011**: 系统 MUST 从持仓页面实时获取当前持仓总金额用于盈利计算,每次用户选择日期范围后重新查询
- **FR-011a**: 如果实时查询持仓数据失败,系统 MUST 显示错误提示并引导用户检查持仓系统状态
- **FR-012**: 资金明细列表 MUST 按日期倒序排列,最近的日期显示在列表顶部
- **FR-012a**: 资金明细列表 MUST 采用无限滚动加载方式,初始加载20条记录,滚动到底部时自动加载更多

### Key Entities *(include if feature involves data)*

- **资金明细记录(FundDetailRecord)**: 代表一笔资金变动记录,包含以下属性:唯一标识符、日期、金额(正数)、资金类型(枚举值:"IN"转入/"OUT"转出/"DIVIDEND"股息/"DIVIDEND_TAX"股息扣税)、账户余额(计算得出)、创建时间、更新时间
- **账户配置(AccountConfig)**: 代表账户配置信息,包含以下属性:唯一标识符、账户余额、最后更新时间
- **盈利统计(ProfitStatistics)**: 代表指定时间段内的盈利计算结果,包含:开始日期、结束日期、转入总金额、转出总金额、账户余额、当前持仓金额、盈利金额

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在30秒内完成一笔转账记录的添加操作
- **SC-002**: 转账记录列表初始20条记录在1秒内加载完成,后续滚动加载更多时每批20条记录在0.5秒内加载
- **SC-003**: 盈利统计结果在用户选择日期范围后1秒内计算并显示
- **SC-004**: 95%的用户能够独立完成转账记录的增删改操作而无需帮助
- **SC-005**: 盈利计算准确率达到100%,与手动计算结果完全一致

## Assumptions

- 用户已经熟悉股票持仓管理功能,当前持仓金额可以从现有的持仓系统中获取
- 转账记录的日期默认为当天,但允许用户修改为其他日期
- 转入表示资金进入账户(增加可用资金),转出表示资金离开账户(减少可用资金)
- 盈利统计中的"当前持仓金额"指的是统计时间点的所有持仓股票的总市值
- 系统采用本地数据库存储转账记录,不需要云端同步功能
- 转账金额使用人民币(CNY)作为货币单位
- 用户界面采用中文显示,符合中国用户的使用习惯
